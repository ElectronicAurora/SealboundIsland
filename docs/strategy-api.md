# AI 刻印策略插件 · 接口说明

> 适用版本：**2.3.9+** ｜ 对应 `index.html`
> 插件只接管 AI 的**两个决策点**：选刻印、攻击上色。规则、伤害、结算一律不动。

---

## 1. 它是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 一个可以单独分发的 `.js` 文本文件 | 不是外挂：不读存档、不改内存、不改规则 |
| 只回答「选哪个 / 上什么色」 | 不参与移动、攻击目标、道具使用等其它 AI 行为 |
| 装载后可随时卸载，回到内置逻辑 | 不是必备项：不装就和以前完全一样 |

设计上把插件放在**最后一道闸门前**：它给建议，主程序校验合法性，非法就静默回落内置。
所以一个写错的策略最差表现是「AI 变回原来的样子」，不会卡死、不会崩、不会产生非法状态。

---

## 2. 怎么用

### 2.1 图形界面（推荐）

1. 开始界面 → **设置** → 找到「AI 刻印策略」一行
2. 点 **导入策略…** → 三种方式任选：
   - **选文件**：挑本地 `.js`（推荐）
   - **从链接**：填 GitHub 的 raw 地址（`file://` 打开的页面拿不到跨域，会明确报错）
   - **直接粘贴**：把代码贴进文本框
3. 应用后日志里出现 `【AI 策略】已装载策略「…」` 即生效（**下一局起**，当前局不换脑子）
4. 想回去：**卸载** 按钮

### 2.2 从 GitHub / 网页应用

插件是纯文本，所以最省事的分发就是放进仓库：

```
你的仓库/
  index.html
  strategies/
    default.js
    my-bot.js
```

用户点进 `my-bot.js` → 右上角 **Raw** → 复制地址 / 直接全选复制，
在「导入策略…」里选「从链接」或「直接粘贴」。

> 用 `https://` 托管（GitHub Pages、任意静态托管）时「从链接」可直接拉取；
> 本地双击打开的 `file://` 页面受同源限制，只能「选文件」或「粘贴」。

## 3. 文件结构

一个策略文件就是一段普通脚本，**必须**在顶层（或任意可执行位置）给 `STRATEGY` 赋值：

```js
const STRATEGY = {
  name: '我的策略',           // 可读名字，装到界面和日志里
  pickSeal(ctx) { ... },      // 可选
  pickSealBranch(ctx) { ... },// 可选：占位型分支（如 ⑧）
  pickPaint(ctx) { ... }      // 可选
};
```

三点约束：

1. **至少要有 `pickSeal` 或 `pickPaint` 之一**，否则装载直接失败并提示。
2. 文件在 `new Function` 沙箱里执行，拿不到页面局部变量。要用游戏功能只能靠 `ctx`。
3. **不要在这里改游戏状态**（不要写 `p.hp = 99` 之类）。策略是"建议"，不是"执行"。
   即使写了，也会被主程序的合法性校验挡在很多地方之外，但请不要依赖这一点。

### 3.1 返回 `null` / `undefined` = 回落内置

这是整个接口最重要的约定：

```js
pickSeal(ctx){
  if (ctx.me.hp > 10) return null;      // 血厚不用管，交回内置
  return '5';                            // 只有残血时才插手
}
```

反过来说，**返回 `null` 永远不会出错**。所以可以只覆盖你关心的场景，
其余全部还给内置 —— 这也是做 A/B 对照实验最方便的方式。

### 3.2 出错会怎样

| 情况 | 处理 |
|---|---|
| 返回了不在 `ctx.candidates` 里的 id | 记一条日志 + 该次回落内置 |
| 抛异常 | 记日志 + 该次回落内置 + 错误计数 +1 |
| **连续 3 次**抛异常 | 自动卸载，回到内置，日志提示 |

"连续"指中间没有一次成功返回。只要有一次正常返回就清零。

## 4. `pickSeal(ctx)` — 选刻印

### 4.1 返回

一个**字符串 id**，必须出现在 `ctx.candidates` 里。

```js
return '9';                     // ⑨裂帛
return '12b';                   // ⑫尘梦的分支（当选且合法时）
return null;                    // 回落内置
```

### 4.2 `ctx.candidates` 里都有什么

| 类别 | 例子 | 什么时候出现 |
|---|---|---|
| 基础刻印 | `'1'`…`'13'` | 未持有，或该刻印可叠加（③丰穰 / ①劫雷 / ⑦蹑景） |
| 单分支 | `'6b'` `'9b'` `'12b'` `'4b'` `'5b'` `'2b'` `'10b'` `'13b'` `'11b'` | 已持有对应基础项，且分支没选过 |
| 凌波分支① | `'8a'` | 总是可选（可叠加，层数不限） |
| 凌波分支② | `'8b'` | 已有 `8a` ≥ 1 层；**拿过也还在**（同样可叠加） |
| 占位入口 | `'8'` | 已持有 ⑧ 且分支未选 —— **返回它会让主程序再问你一次 `pickSealBranch`** |

> **关于 ⑧凌波**：内置 AI 直接返回 `'8a'` / `'8b'`，不走占位入口。
> 你想让它先选 ⑧ 再分支，就返回 `'8'`；想直接指定分支，就返回 `'8a'` / `'8b'`。两种都合法。

最稳的写法永远是先查一遍：

```js
const can = id => ctx.candidates.indexOf(id) >= 0;
if (can('12b')) return '12b';
```

### 4.3 `ctx` 字段

```js
ctx.me      // 自己
ctx.target  // 选印时恒为 null（没有目标）
ctx.field   // 局面聚合值
ctx.rules   // 规则常量
ctx.candidates // 可选项 id 数组
```

`ctx.me` / `ctx.target` 是同构快照：

| 字段 | 含义 |
|---|---|
| `hp` / `maxHp` | 当前 / 最大血量 |
| `atk` / `def` | 最终攻击 / 防御（已算武器、刻印、状态） |
| `dust` | 【尘】层数（每层减伤 1；增伤需 ⑫b） |
| `tear` / `tear9b` | 【撕裂】层数 / 其中来自 ⑨b 的层数 |
| `blue` / `yellow` / `white` | 【蓝】布尔 / 【黄】层数 / 【白】布尔 |
| `isSummon` | 是否召唤物 |
| `seals` | `{id: 层数}` 全部持有刻印，含分支键（`{'9':1,'9b':1,'8a':2}`） |
| `blacked` | 被【黑】封住的刻印 id 数组 |

`ctx.field`：

| 字段 | 含义 |
|---|---|
| `round` | 当前回合数（第几轮） |
| `mode` | `'ffa'`（混战） / `'team'` 等 |
| `aliveFoes` / `aliveMates` | 存活敌人数 / 队友数 |
| `avgFoeDust` | 敌方平均【尘】层数 |
| `gear` | 背包里护甲 + 武器件数（⑬盈箧判据） |
| `hasSummon` | 已有召唤物或持有召唤道具（⑩御灵判据） |
| `summonCount` | 当前召唤物数量 |

`ctx.rules`（规则常量，写死，方便策略自解释）：

```js
{ dustReducePerLayer: 1, dustAtkNeeds: '12b', tearPermanent: true,
  tearDmgPerLayer: 1, blackCanPreSeal: true }
```

### 4.4 写一个最简策略

```js
const STRATEGY = {
  name: '血薄就抱残锋',
  pickSeal(ctx){
    const can = id => ctx.candidates.indexOf(id) >= 0;
    if (ctx.me.maxHp <= 8 && can('5')) return '5';   // 残锋：临界越低越强
    return null;                                      // 其余交给内置
  }
};
```

## 5. `pickSealBranch(ctx)` — 分支二选一

只有当 `pickSeal` 返回了占位入口 `'8'` 时才会被问到。

```js
pickSealBranch(ctx){
  // ctx.baseId === '8'
  // ctx.candidates === ['8a','8b']
  return (ctx.me.seals['8a'] || 0) >= 2 ? '8b' : '8a';
}
```

| 约定 | 说明 |
|---|---|
| `ctx.baseId` | 基础刻印 id |
| `ctx.candidates` | 该基础的子键数组 |
| 返回其他任何值 | 该次回落内置 |

> 目前只有 ⑧凌波是多分支（`placeholder: true`）。
> 其余 `6b / 9b / 12b / 4b / …` 都是单分支，选了就直接生效，不会问到这里。

## 6. `pickPaint(ctx)` — 攻击命中附加色

### 6.1 返回

| 返回 | 含义 |
|---|---|
| `'red'` / `'blue'` / `'yellow'` | 对应单色 |
| `'white'` | 【白】（需 ⑪b） |
| `{ color:'black', sealId:'5' }` | 【黑】封目标的 ⑤（需 ⑪b） |
| `{ color:'grey', clearKey:'dust' }` | 【灰】解掉目标身上的一项（需 ⑪b） |
| `null` | 不上色 / 回落内置 |

### 6.2 `ctx.candidates` 里的颜色

- 未拿 ⑪b：`['red','blue','yellow']`
- 已拿 ⑪b：`['red','blue','yellow','white','black','grey']`

这与人类玩家的可选范围**完全一致**，主程序不会给 AI 开小灶。

### 6.3 黑：`sealId` 怎么填

```
1 劫雷   2 同契   3 丰穰   4 敕禁   5 残锋   6 天工   7 蹑景
8 凌波   9 裂帛  10 御灵  11 点染  12 尘梦  13 盈箧
```

- 填 `'11'` 会被拒绝（黑不能黑黑）
- **可以封目标还没拿到的刻印**（预先封锁，等他选到当场失效）—— 这是【黑】的核心价值
- 同一项已经封过再封会被拒绝（回落内置）

### 6.4 灰：`clearKey` 可选值

`clearKey` 必须**在目标身上真实存在**，否则回落内置。用 `paintClearCandidates` 的同一套键：

| key | 解除 |
|---|---|
| `'white'` | 【白】 |
| `'blue'` | 【蓝】 |
| `'yellow'` | 【黄】 |
| `'tear'` | 【撕裂】（含 ⑨b 附加的 DEF 惩罚） |
| `'dust'` | 【尘】（整层清零） |
| `'black:<id>'` | 指定一项【黑】，如 `'black:11'` |
| `'precept:<i>'` | 第 i 条【戒律】 |
| `'sanction:<i>'` | 第 i 条【敕罚】 |

> 灰是【黑】的第二条解除路径：可以直接按下标解掉对方身上某一项黑。

### 6.5 例

```js
pickPaint(ctx){
  const t = ctx.target;
  const can = c => ctx.candidates.indexOf(c) >= 0;
  if (!t) return null;

  // 对方厚尘：撕开减伤通道
  if (can('grey') && t.dust >= 4) return { color:'grey', clearKey:'dust' };

  // 对方即将爆发：预先封掉他的 ⑨裂帛（还没拿到也照样封）
  if (can('black') && t.atk >= 9) return { color:'black', sealId:'9' };

  // 对方血薄：补撕裂
  if (can('red') && t.hp <= 6) return 'red';

  return null;
}
```

## 7. 基线：`strategies/default.js`

仓库自带一份**与内置逻辑逐字等价**的基线：

```
strategies/
  default.js     ← 基线，分数表照抄内置 aiPickSeal
  example.js     ← 示例，演示接口能干什么（不承诺强度）
  manifest.json  ← 索引
```

它存在的意义是做**对照实验**：装它和不装它，AI 的决策分布必须完全一致。
实测 12 局 × 4 人 × 6 次授印，16 项刻印分布差异 **0 / 16**。

写自己的策略时建议 **复制 `default.js` 再改**，而不是从零开始 ——
内置那套分数是调过的，直接扔掉容易写出比原来更差的 AI。

### 7.1 改分数时注意

内置用的是**加权随机**（不是取最高分）：

```js
sc.sort((a,b) => b.s - a.s);
const sum = sc.reduce((s,x) => s + x.s, 0);
let r = Math.random() * sum;
for (const x of sc) if ((r -= x.s) < 0) return x.id;
```

这意味着：

- 分数只有**相对比例**有意义，整体放大缩小不影响结果
- 但改 5~10 分就足以改变可观测分布（实测：⑧a 从 17 掉到 13）
- 所以做对照实验时，**先跑通基线再说**

## 8. 调试建议

1. **日志**：装载 / 卸载 / 抛错 / 非法返回都会写进游戏日志（`【AI 策略】` 前缀）
2. **先返回 null 试水**：能装载、能跑、不报错，再一点点加逻辑
3. **用 `ctx.candidates` 兜底**：任何返回值前先 `indexOf` 查一遍，永远不会踩非法返回
4. **别怕卸载**：界面「卸载」随时回内置，当前局不受影响（决策是即时的）

## 9. 已知边界

| 边界 | 说明 |
|---|---|
| 只在**授印**和**攻击上色**生效 | 移动、攻击目标、道具、技能释放仍是内置 AI |
| 装载后**下一局**才生效 | 当前局已经跑的决策不会重算 |
| 不持有 ⑪b 时没有黑 / 灰 / 白 | 与人类玩家同一口径，不是插件的限制 |
| 灰必须解真实存在的项 | 目标身上没有就回落，不会凭空生效 |
| ⑧b 需要 ⑧a ≥ 1 层 | 前置不满足时 `'8b'` 不进候选；满足后一直可选（可叠加） |
