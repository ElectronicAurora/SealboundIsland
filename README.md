# 末环协议 · RingFall

> 单文件 HTML5 回合制生存游戏 —— 零依赖，双击即玩。

`index.html` 一个文件就是全部：程序、资源、AI 全在里面，不联网、不装环境、没有外部 CDN。从本地直接用浏览器打开即可开局。

---

## 快速开始

1. 下载 [`index.html`](index.html)（约 400 KB）。
2. 双击，或拖进任意现代浏览器（Chrome / Edge / Firefox / Safari 均可）。
3. 在设置面板选好模式、人数、HP，点开始。

> 在线托管（可选）：把 `index.html` 推到 GitHub 仓库后开启 **GitHub Pages**，即可得到一个可分享的游玩链接。本地 `file://` 打开也完全正常，唯一区别是 AI 经验库会降级为内存模式（关页即清，不影响游玩）。

## 这是个什么游戏

2–6 名玩家散落在各自的岛屿上，回合制互相打，**活到最后**。地图会随回合收缩（孤悬的岛屿会坠落），资源藏在箱子与商店里，核心成长来自 **13 枚刻印** 的组合。

### 三种模式

| 模式 | 胜负条件 |
|---|---|
| 单人混战（FFA） | 只剩 1 名存活玩家 |
| 自定义分队 | 只剩 1 支队伍（同队不可互殴） |
| BOSS 战 | BOSS 血量 `max(10, (n−1)×10)`，英雄方全员仅 **1 HP**，赌一击毙命 |

### 双地图

- **孤枢散星**（star）——放射状外岛 + 中心枢纽。
- **叠嶂凝芒**（hub）——层层环抱的中心岛，箱子无限刷新，适合拉锯。

### 核心机制速览

- **点染**：命中后附加【红】（撕裂）/【蓝】（禁攻）/【黄】（禁移）三色之一；选 11b 分支才解锁【白】（禁指向）/【黑】（封能力）/【灰】（解效果）。
- **【尘】**：每层减伤 1 点，普通攻击要同时打穿 DEF 和尘 —— 叠厚了能把对手「挡死」，逼对方换真实伤害手段。
- **遗器 / 召唤物 / 炮台**：沧溟之眼（真实伤害分配）、七弦连射、斩月斩杀、忘川均分、掷星掷点、心渊精神控制，共 6 件遗器各有专属规则；另有召唤兽与机械炮台。
- **掷星**：掷 1 ~ 本局开局时最高玩家 HP 上限的真实伤害（开局定死，含已阵亡者），点数若是质数（1 不算）再得一个额外回合。
- **心渊**：净化（解一个状态）+ 掌控（精神控制一名实体至你的下个主要回合，期间其所有行动由你操纵；不能连控同一目标）。
- **戒律 / 敕罚**：禁止行动类（戒律）与违反即掉血类（敕罚）状态，同类只结一次。

完整规则见 **[规则书.md](规则书.md)**（约 72 KB，全部条款以程序实际行为为准，函数名可对账）。

## AI

程序内置完整决策 AI，可全托管观战，也可只给部分玩家托管。特性：

- 分段决策：发育 → 交战 → 收尾，按局势分档切换策略。
- **前瞻预判**：预判对手威胁与岛屿坠落风险，危险时主动转移。
- **破壁意识**：普通攻击被【尘】挡死时，自动改用沧溟【分配】或蓄力远程。
- **经验库**：AI 会跨局学习 —— 结算后对比同局内「做了某决策 vs 没做」的存活表现，微调开箱 / 蓄力 / 集火 / 破壁四类倾向（权重上限 ±25%）。数据存 localStorage，约 211 B，永不膨胀。

> 经验库算法为**同局横向对照**，不是「赢家 +1 胜 / 输家 +1 负」—— 多人局按人数记账会把每项系统性压成负数，故不采用。

### AI 策略插件（2.3.9 新增）

AI 的**选刻印**与**攻击上色**两个决策点支持用外部文件接管，可选装可不装：

- 设置面板 → 「AI 刻印策略」→ **导入策略…** → 选文件 / 从链接 / 直接粘贴。
- 插件只回答「选哪个」，规则与结算一律不动；返回 `null` 即回落内置，抛错连续 3 次自动卸载。
- 不装 = 和以前完全一样。装了以后**下一局**生效。

| 文件 | 说明 |
|---|---|
| [`strategies/default.js`](strategies/default.js) | **基线**：内置逻辑的文字版，装它 / 不装它分布完全一致（实测 16 项差异 0），用于做对照实验 |
| [`strategies/example.js`](strategies/example.js) | **示例**：残血优先 + 解尘灰，演示接口用法（不承诺强度） |
| [`strategies/smart.js`](strategies/smart.js) | **实用**：残血保命 + 破壁联动 + 精准上色，相对内置补三处盲区；残血时会主动为 ⑧b 铺路（先补 ⑧a 到 2 层再转 ⑧b） |
| [`strategies/manifest.json`](strategies/manifest.json) | 策略索引 |
| [`docs/strategy-api.md`](docs/strategy-api.md) | 完整接口文档（`pickSeal` / `pickSealBranch` / `pickPaint`、ctx 字段、六色与 `clearKey` 取值） |

自己写策略时**建议复制 `default.js` 再改** —— 内置那套分数是调过的，直接扔掉容易写出比原来更差的 AI。

## 局域网联机（LAN 联机补丁）

支持 1 名房主 + 多名玩家在同一局域网内联机对战。架构为**房主权威**：回合推进、AI、随机数、结算全部只在房主侧发生，客户端只收画面、上传操作，因此不会有随机数冲突。

### 开联机服（房主电脑）

```bash
npm install ws
node server.js        # 默认端口 8080，可用环境变量 PORT 覆盖
```

server.js 除了 WebSocket 中转，还会**静态托管游戏本体**——队友不用传文件，直接浏览器打开房主地址就能玩。

### 房主

1. 浏览器打开 `http://localhost:8080/`（或直接双击 `index.html`）→ 开局面板 → **作为房主开始**。
2. 按常规配置对局；玩家加入后其对应玩家位会**自动设为人类**（人数不够自动扩充，最多 6 人局）。
3. 点「开始游戏」即可；客户端的画面 / 日志 / 面板会自动同步。

### 客户端

1. 浏览器打开 **`http://房主IP:8080/`**（推荐，地址不用手填）或双击 `index.html` → 开局面板 → **加入房间…** → 输入房主的局域网地址（如 `ws://192.168.1.x:8080`）。
2. 等房主开局，画面自动同步过来；轮到自己时行动栏解锁，点击行动 / 弹面板均会转发给房主执行。
3. 开局后加入的玩家本局座位已固定，等房主「重新设置」或结算后下一局自动入座。

### 行为约定

- **房主权威 + 状态快照 + 面板镜像**：房主每次状态变化后节流广播全量快照（实测约 3.6 KB/次、序列化 0.05 ms），客户端零游戏逻辑只负责显示；随机数、回合推进、结算全部只在房主侧发生，两端看到的结果永远一致。
- **面板 DOM 镜像**：客户端看到的选择面板是房主面板的实时镜像（标题/选项/禁用态完全一致），选择只回传「第几项」，房主在自己页面上点等价按钮执行——刻印自选、商店、分配页等所有 `showChoice` 场景全部自动支持，未来加新面板也无需改补丁。
- 双方的行动栏都只在「轮到自己且归自己管」时亮起；轮到别人时房主侧面板会盖「等待 玩家 X 行动…」遮罩，任何一方都不能替对方操作。
- 玩家卡标签：房主侧 YOU=本机、远程=联机队友；客户端侧 YOU=自己、队友=其他人。掉线队友的座位暂由房主代管，游戏不会卡死。
- 结算画面自动镜像；「再来一局 / 重新设置 / 返回主页面」由房主操作，客户端同步跟随。
- 未连接（纯单机）时补丁所有守卫放行，热座行为与原版完全一致。

| 文件 | 说明 |
|---|---|
| `server.js` | 局域网联机服务器：静态托管游戏页面 + WebSocket 中转（不做任何游戏逻辑；需 `npm install ws`） |

> 联机逻辑已内置在 `index.html` 尾部的「局域网联机补丁 v2（NetPlay）」中，无需额外引入脚本。

## 技术栈

- **HTML5 Canvas 2D** 渲染，原生 JavaScript，**零外部依赖**。
- 无构建步骤、无包管理、无网络请求 —— `node --check` 通过即视为语法完好。
- 浏览器支持：任何支持 Canvas 的现代浏览器；本地 `file://` 与 `http://` 均可运行。

## 版本
